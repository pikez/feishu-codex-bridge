# Repository Guidelines

## Project Context

This repository is a fork maintained for evolving personal requirements. The original project’s complete design intent, architectural history, and constraints are not yet known. Treat current requirements, observed behavior, tests, and repository documentation as the source of truth; verify unclear legacy behavior before changing it.

## Project Structure & Module Organization

- `src/` contains the TypeScript implementation. Key areas include `bot/` for Feishu/Lark interactions, `agent/` for Codex and Claude backends, `cli/` for commands, `web/` for the admin console, `project/` for project/session state, and `service/` for platform services.
- `test/` contains Vitest tests named `*.test.ts`.
- `docs/` holds design notes, release notes, testing notes, and assets. `scripts/` contains deployment and release helpers; `bin/` contains the CLI launcher.
- `dist/` is generated by tsup. Do not edit or commit generated output.

## Build, Test, and Development Commands

- `npm ci` — install the locked dependencies.
- `npm run typecheck` — run strict TypeScript checking without emitting files.
- `npm test` — execute the Vitest suite.
- `npm run build` — bundle the package into `dist/` with tsup.
- `npm run dev` — watch and rebuild during development.
- `npm start` — run the CLI locally; use `bash scripts/dev-run.sh` for a first-time setup and foreground run.
- `./scripts/deploy.sh --dry-run` — preview deployment of this checkout without changing the global install.

## Coding Style & Naming Conventions

Use the existing TypeScript style: two-space indentation, single quotes, semicolons, strict types, and explicit handling of nullable or indexed values. Keep modules focused and use `camelCase` for variables/functions, `PascalCase` for types/classes, and kebab-free lowercase filenames such as `session-store.ts`. No separate formatter or linter is configured; match nearby code and run typecheck/tests before submitting.

## Testing Guidelines

Add or update a focused `test/<area>.test.ts` regression test for behavior changes. Keep unit tests deterministic and isolate external Feishu, filesystem, process, and backend boundaries with fakes or mocks. Run `npm test` and `npm run typecheck`; live tests (for example, `*.live.test.ts`) may require local credentials or services and should be called out explicitly.

## Commit & Pull Request Guidelines

Use concise Conventional Commit subjects such as `feat(session): ...`, `fix(settings): ...`, `docs: ...`, or `chore(release): ...`. Keep each commit focused. Pull requests should explain the behavior change and fork-specific rationale, list validation commands, link related issues when available, and include screenshots or recordings for web/card UI changes. Never include tokens, bot secrets, or personal local state.
